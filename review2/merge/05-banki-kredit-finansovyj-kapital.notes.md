## в) Конфликты и их разрешение

1. **Знаменатель долей 50,6% (РФ) / 29,3% (КНР).** A и C (+ база + SRC-013) относят доли
   к **внешнему долгу банковского сектора** (остаток, 01.01.2025); B (следуя формулировке
   рецензии об «обновлённом ядре») — к **государственному долгу по кредиторам**.
   Решение: банковский сектор, как в базе с SRC-013. Основания: приоритет базы/стандарта
   (разведение показателей, п. I.8 ядра; SRC-013 в реестре описывает банковский внешний
   долг $2,9 млрд); большинство (A+C); сама рецензия не даёт источника для госдолг-версии
   и требует лишь «установить знаменатель» — это требование выполнено (знаменатель указан
   явно, структура госдолга по кредиторам — отдельное [задание]). При подтверждении иного
   знаменателя — пересмотр по SRC-013.
2. **Конфликт id между прогонами.** Один диапазон SRC-083+/CLM-084+ независимо занят
   разными записями у A, B и C (например, SRC-083 у A — договор Белтрансгаза, у B —
   сообщение «Газпрома», у C — НБРБ прил. 3; CLM-084 у A — гл. 3, у B — гл. 1, у C —
   гл. 5). В текст merge новые id сознательно не вносились — только базовые коды;
   распределение кандидатов — в таблице выше. Финальную нумерацию назначает координатор
   при слиянии реестров.
3. **Персональная уния.** База: «координация через административную вертикаль, а не
   персональная уния» (форма-оговорка). Рецензия: без кадровых данных писать «не
   установлена». A — «персональная уния не установлена, установлена административная
   вертикаль»; B — таблица трёх форм; C — «снята». Согласовано без остатка: не установлена
   (статус доказательств), административная координация установлена, влияние через кредит —
   отдельный открытый вопрос.
4. **Объём.** C сжал главу до ~125% базы, A/B расширили до ~195/215% (в байтах к исходнику
   21 562 Б). Рецензия требует полноты (добавить 6 содержательных блоков, 5 таблиц),
   поэтому сжатие C не аргумент; merge ~262% базы — объединение непересекающихся блоков
   A/B/C и вставок по рецензии с переносом лучших решений и снятием повторов (требование
   рецензии 4.5).

## г) Плейсхолдеры SVG

В главе было два новых плейсхолдера, **оба отсутствуют в генераторе схем книги**
(существующие имена: axes, contour, energy, fdi, iip, map, milex, potash, program, trade):

- A: `{{SVG:credit-flow}}` (§5.6) — «государство → кредитные решения → банк → предприятие
  → доходы/убытки → государственное перераспределение»; сплошные стрелки — установленные
  звенья, пунктир — предполагаемые.
- C: `{{SVG:kreditnyj-potok-05}}` (§5.3) — то же с подписью: сплошные — подтверждённые
  (государство → программа → банк → предприятие), пунктирные — требующие проверки
  (условия кредита → решение; проценты и прибыль → перераспределение).

**Решение: оба плейсхолдера убраны, содержание передано текстом** (по варианту B, §5.3).

Обоснование: (1) нерендерящийся плейсхолдер остался бы артефактом в итоговом тексте;
(2) мысль схемы не критична для доказательства — она дублируется таблицей карточки 1 §5.6
и текстовой схемой, где различение доказанных стрелок («государство → кредитные решения»,
«банк → предприятие») и предполагаемых («кредитные решения → условия кредита»,
«предприятие → доходы/убытки», «→ государственное перераспределение») проведено явно,
включая формулу «недостающее звено — между направлением кредита и механизмом присвоения»;
(3) требование рецензии P2.3 («добавить схему движения кредита, доходов и рисков»)
выполнено в текстовой форме — навигационную функцию схема выполняет и как текст.
