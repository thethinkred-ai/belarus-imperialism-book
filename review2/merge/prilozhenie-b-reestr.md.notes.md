## г) Конфликты между вариантами (и со стандартом)

1. **§Б.6: рецензия требует заменить статический «полный список» на динамическую карту;
   особое указание координатора требует в §Б.6 ПОЛНЫЙ список SRC-001…082.** Принято
   указание координатора: полный список сохранён (сгенерирован из реестра), дополнен
   оговоркой «актуален реестр, перечень — снимок» (компромисс с рецензией P1-1); требование
   рецензии об автоматической генерации перечня при сборке — помечено координатору (см. д).
2. **Счётчики: A/B дали «62/83 на снимок v0.7.1»; C убрал все числа («приложение реестр не
   правит»).** Особое указание координатора — числа «62 источника, 83 утверждения» в тексте
   сохранить как есть → принята A/B-форма с привязкой к автообновляемому реестру.
3. **B упоминал свои предложения SRC-083 и CLM-084…091 (registry-add.json) в §Б.1.** Отклонено
   по особому указанию (предложения агентов в прил. Б не переносятся) — координатор возьмёт
   их из agent-b/registry-add.json напрямую.
4. **Группировка новых SRC в §Б.3: A — отдельный блок «Новые группы данных»; B — растворил
   новые SRC в старых группах (с ошибками: SRC-059 «бюджетные законы» попал в «отраслевые
   и корпоративные»).** Принято A (соответствует рецензии «короткий блок "Новые группы
   данных"») с исправленным составом (058 — газ в пару к 073; 059 — бюджетные законы).
5. **Статусы карточек: A перечислил «подтверждено, частично, не проверено, опровергнуто,
   мониторинг»; C — «supported/partial/unverified/refuted/monitoring».** Сверка с реестром:
   фактические значения на снимок — supported×72, partial×9, unverified×2; формулировка
   merge уточнена («схемой также предусмотрены…, на текущий снимок не встречаются»).
6. **Упоминание Telegram: A сохранил ссылку и «напишите»; B/C убрали ссылку, C — безличное
   «сообщите».** Принято C-решение по глаголу (безличная форма) при сохранении ссылки базы
   (t.me/thinkred_marx — канал проекта, железное правило допускает упоминание канала как
