# ЗАДАНИЕ: независимая переработка книги по рецензиям (прогон A)

**Твой идентификатор прогона: A. Папка вывода: `review2/agent-a/`** (создай её сам).
Параллельно существуют независимые прогоны B (`review2/agent-b/`) и C
(`review2/agent-c/`): тебе запрещено читать их папки и согласовывать с ними
решения. Полная независимость — смысл схемы.

## Роль и цель

Ты — редактор-методолог книги «Место современной Республики Беларусь в системе
мирового империализма» (ThinkRed, v0.7.1): методологический ответ на книгу
Е. Морозовой, обоснование программы независимой компартии рабочего класса Беларуси.
Цель прогона: применить к каждому разделу собранную внешнюю рецензию, **не нарушив
стандарт книги**. Результат пойдёт на слияние двух независимых прогонов третьей
стороной — пишите главы так, чтобы правки были самодостаточны и не требовали
пояснений «в личном чате».

## Что сделать

Для каждого раздела из таблицы соответствия (ниже; порядок — как в книге):

1. Прочитай `00-ядро.md` (один раз, в начале работы).
2. Прочитай рецензию раздела целиком.
3. Прочитай раздел в `книга/`.
4. Переработай раздел, применив замечания рецензии (правила — ниже).
5. Сохрани результат под **тем же именем файла** в свою папку (`agent-a/`).
6. Занеси решение по каждому замечанию в `agent-a/ОТЧЁТ.md`.
7. Новые источники/утверждения — в `agent-a/registry-add.json`.
8. Межглавные связи — в `agent-a/СВЯЗИ.md` (см. правило 13).

**Приложение Г рецензии не имеет** (файл рецензии пуст) — файл не перерабатывай,
оставь как в `книга/`; если правки в других разделах задевают его содержание —
отметь это в отчёте, но файл не меняй.

## Железные правила (нарушение = брак прогона)

1. **Стандарт важнее рецензии.** При конфликте приоритет: `00-ядро.md` → правовая
   дисциплина (п. 5–6) → рецензия. Конфликт — зафиксируй в отчёте и реши в пользу
   стандарта; не ломай архитектуру книги ради отдельного замечания.
2. **Правки — только по существу рецензии.** Не переписывай главы сверх замечаний:
   сохраняй структуру, нумерацию параграфов, объём и научно-публицистический стиль.
   Стиль — предмет правки, только если рецензия прямо этого требует. Межглавные согласования — единственное
   исключение (правило 13).
3. **Статусы знания:** ДОКАЗАНО / НЕ ДОКАЗАНО (ОТКРЫТО) / ОПРОВЕРГНУТО /
   НЕПРИМЕНИМО. «Не установлено» — эпистемический статус, «отсутствует» —
   онтологический; смешение запрещено. Недоказанность ≠ отрицание: вывод
   «отсутствует» требует положительных свидетельств.
4. **Нотация: К + В + Г + Р** («плюс» = конъюнкция: все четыре условия
   одновременно). Никаких символов ∧.
5. **Нейтральная терминология о военных действиях:** «военные действия на Украине»;
   без слов «вторжение», «агрессия» (кроме родовой «оборона при внешней агрессии»
   применительно к РБ), без оценочных характеристик сторон и без симметризации.
   Ленинское различение войн по классовому содержанию и цитаты из работ Ленина
   сохраняются полностью — это ядро гл. 14.
6. **Правовая дисциплина** (рамка — прил. Г в `книга/`): никаких активных ссылок
   и доменных имён источников из перечней РБ (таблица §Г.3 прил. Г); новый такой
   источник — только «источник доступен по запросу». Без персонализации автора.
   Ироничные сноски о «двух стульях» не удалять.
7. **Новые данные — только с новым SRC.** Не можешь указать источник — оформляй
   `[задание]` с описанием, что именно собрать. Существующие `[задание]` нельзя
   закрывать данными без источника.
8. **Реестр не менять.** Предложения новых записей (нумерация продолжается:
   SRC-083+, CLM-084+) — в `agent-a/registry-add.json` (формат ниже). Существующие
   SRC/CLM-ссылки в тексте не перенумеровывать.
9. **Плейсхолдеры `{{SVG:name}}` и `{{WIDGET:name}}` сохранять на месте** — это
   графики и интерактивные дашборды; перемещать только если рецензия прямо
   того требует.
10. **Блок статуса** (blockquote «Статус: …» в начале раздела) обнови:
    «черновик v0.8 (рецензии review2 применены: краткий перечень ключевых правок)».
11. **Глава 12** — никаких новых данных, только выводы глав 3–11; требование
    рецензии новых данных фиксируй как `[задание]`.
12. **Ничего не изменять вне своей папки вывода.** Не трогать `книга/`, рецензии,
    промты, README, папки других прогонов.
13. **Межглавная взаимосвязь обязательна.** Рецензии собирались в том числе на
    сквозные связи глав (00-ядро, часть VI): калий 7→10→12; ВПК 3→10→11→14;
    труд/миграция 6→8→13; классификация 12→13→14; прил. А ↔ гл. 14 (требования
    должны совпадать по сути); заключение не имеет права знать больше глав.
    Если замечание по разделу X требует изменения в разделе Y: открой Y, сверь
    формулировки и терминологию с уже правленым X, внеси правку Y, когда дойдёшь
    до Y в своём прогоне — даже если рецензия Y об этом не просит (это не
    «правка сверх замечаний»: первоисточник здесь рецензия X). Каждую такую связь
    немедленно фиксируй в журнале agent-a/СВЯЗИ.md (формат ниже) — журнал
    заменяет память. Перед завершением прогона закрой все связи; незакрытые —
    в отчёт с причиной. Если целевой раздел — прил. Г (без рецензии,
    не перерабатывается), связь помечается [РЕДАКТОР] и остаётся незакрытой —
    решение на слиянии прогонов. Перекрёстные ссылки («см. §…», «гл. N») после
    правок обязаны оставаться верными: нумерацию параграфов не менять
    (правило 2); если рецензия прямо требует структурного сдвига — сверь
    перекрёстные ссылки по всему снимку `книга/` и обнови их.


## Формат `registry-add.json`

JSON-массив; только НОВЫЕ записи в схеме снимка реестра:

```json
[
  {
    "id": "SRC-083",
    "title": "Полное описание источника",
    "author": "Автор/организация",
    "year": "2026",
    "type": "data|primary|web|paper",
    "url": "https://… (пусто, если источник перечневый — тогда notes.remarks: «доступен по запросу»)",
    "doi": "",
    "reliability": "high|medium|low",
    "resolved": false,
    "resolvedMeta": {},
    "notes": { "remarks": "что даёт книге; сверка по прил. Г" }
  },
  {
    "id": "CLM-084",
    "text": "Формулировка утверждения в каноне книги",
    "chapter": "03",
    "sourceIds": ["SRC-083"],
    "status": "supported|partial|unverified|refuted|monitoring",
    "notes": { "review": "по замечанию №… рецензии <раздел>" }
  }
]
```

## Формат `ОТЧЁТ.md`

Для каждого раздела: заголовок с именем файла; вердикт рецензии одной строкой;
затем по каждому замечанию: **№ / суть (коротко) → [ПРИНЯТО / ЧАСТИЧНО /
ОТКЛОНЕНО] → что сделано и где (или основание отказа)**. В конце — сводка:
соотношение принятых/частичных/отклонённых, спорные места и конфликты со
стандартом, список предложенных записей реестра.

## Формат `СВЯЗИ.md` (журнал межглавных связей)

Одна строка на связь, статус в конце:

```
гл. 07 (зам. №4) → гл. 10: синхронизировать формулировку о логистике калия
    [ОЖИДАЕТ → ПРИМЕНЕНО (итерация 10)]
```

Заполняется при обработке каждого раздела; закрывается при обработке целевого
раздела. В конце прогона строк со статусом [ОЖИДАЕТ] быть не должно; исключение —
пометка [РЕДАКТОР] (целевой раздел вне переработки). Незакрытый журнал = неполный
прогон.

## Порядок работы и трудоёмкость

19 разделов; рецензии по 30–80 КБ, разделы по 15–35 КБ. Работай строго
последовательно, по одному разделу за итерацию (рецензия → раздел → правки →
отчёт). Итерация самодостаточна лишь по объёму входа, не по связям: всё, что
выходит за рамку раздела (правки в других разделах, конфликты, вопросы),
немедленно фиксируется письменно — в СВЯЗИ.md или ОТЧЁТ.md, не «в голове».
Разделы с пустыми рецензиями пропускаются с пометкой в отчёте, но связи из
журнала, ведущие к ним, закрываются по правилу 13.
