## Обязательный порядок

1. Прочитай `00-ядро.md` (стандарт книги — приоритет над всем).
2. Прочитай `книга/prilozhenie-g-pravovoj-risk.md` (правовая дисциплина; таблица §Г.3 —

4. Прочитай целиком раздел в `книга/`, указанный в твоём задании.
5. Переработай раздел, применив замечания рецензии (правила ниже).
6. Сохрани результат под тем же именем файла в `agent-a/`.
7. Напиши по-замечанийный отчёт в `agent-a/reports/<имя файла>.md`.
8. Верни в финальном сообщении компактную JSON-сводку.

## Железные правила (нарушение = брак прогона)

1. **Стандарт важнее рецензии.** Приоритет: `00-ядро.md` → правовая дисциплина
   (п. 5–6) → рецензия. Конфликт — зафиксируй в отчёте и реши в пользу стандарта;
   не ломай архитектуру книги ради отдельного замечания.
2. **Правки — только по существу рецензии.** Не переписывай раздел сверх замечаний:
   сохраняй структуру, нумерацию параграфов, объём и научно-публицистический стиль.
   Стиль — предмет правки, только если рецензия прямо этого требует.
3. **Статусы знания:** ДОКАЗАНО / НЕ ДОКАЗАНО (ОТКРЫТО) / ОПРОВЕРГНУТО / НЕПРИМЕНИМО.
   «Не установлено» — эпистемический статус, «отсутствует» — онтологический; смешение
   запрещено. Недоказанность ≠ отрицание: вывод «отсутствует» требует положительных
   свидетельств.
4. **Нотация: К + В + Г + Р** («плюс» = конъюнкция: все четыре условия одновременно).
   Символа ∧ в книге быть не должно.
5. **Нейтральная терминология о военных действиях:** «военные действия на Украине»;
   без слов «вторжение», «агрессия» (кроме родовой «оборона при внешней агрессии»
   применительно к РБ), без оценочных характеристик сторон и без симметризации.
   Ленинское различение войн по классовому содержанию и цитаты из Ленина сохраняются
   полностью — это ядро гл. 14.
6. **Правовая дисциплина** (рамка — прил. Г в `книга/`): никаких активных ссылок и
   доменных имён источников из перечней РБ (таблица §Г.3 прил. Г); новый такой
   источник — только «источник доступен по запросу». Без персонализации автора.
   Ироничные сноски о «двух стульях» не удалять.
7. **Новые данные — только с новым SRC.** Не можешь указать источник — оформляй
   `[задание]` с описанием, что именно собрать. Существующие `[задание]` нельзя
   закрывать данными без источника.
8. **Реестр не менять.** Предложения новых записей (нумерация продолжается:
   SRC-083+, CLM-084+ — назначает координатор) — в отчёт (формат ниже). Существующие
   SRC/CLM-ссылки в тексте не перенумеровывать.
9. **Плейсхолдеры `{{SVG:name}}` и `{{WIDGET:name}}` сохранять на месте** — это графики
   и интерактивные дашборды; перемещать только если рецензия прямо того требует.
10. **Блок статуса** (blockquote «Статус: …» в начале раздела) обнови:
    «черновик v0.8 (рецензии review2 применены: краткий перечень ключевых правок)».
11. **Глава 12** — никаких новых данных, только выводы глав 3–11; требование рецензии
    новых данных фиксируй как `[задание]`.
12. **Ничего не изменять вне своей папки вывода.** Не трогать `книга/`, рецензии,
    промты, README, папку `agent-b/`. Если правки задевают содержание прил. Г —
    отметь это в отчёте, но файл прил. Г не меняй.

## Формат отчёта (файл `agent-a/reports/<имя файла>.md`)

- Заголовок: имя файла раздела.
- Вердикт рецензии одной строкой (первая строка рецензии: «готова с правками» /
  «требует переработки» + почему).
- Затем по каждому замечанию рецензии: `**№ / суть (коротко) → [ПРИНЯТО / ЧАСТИЧНО /
  ОТКЛОНЕНО] → что сделано и где (или основание отказа).**`
- В конце — сводка: соотношение принятых/частичных/отклонённых; спорные места и
  конфликты со стандартом; список предложенных записей реестра.

Каждое замечание рецензии должно попасть в отчёт с вердиктом. Будь консервативен:
не добавляй собственных идей сверх рецензии; неясное или противоречащее стандарту
замечание — ОТКЛОНЕНО с обоснованием.

## Формат предложений реестра (внутри отчёта, JSON-массив)

Только НОВЫЕ записи; id — плейсхолдеры `SRC-000`/`CLM-000` (координатор перенумерует):

```json
[
  {
    "id": "SRC-000",
    "title": "Полное описание источника",
    "author": "Автор/организация",
    "year": "2026",
    "type": "data|primary|web|paper",
    "url": "https://… (пусто, если источник перечневый — тогда notes.remarks: «доступен по запросу»)",
    "doi": "",
    "reliability": "high|medium|low",
    "resolved": false,
    "resolvedMeta": {},
    "notes": { "remarks": "что даёт книге; сверка по прил. Г" }
  },
  {
    "id": "CLM-000",
    "text": "Формулировка утверждения в каноне книги",
    "chapter": "03",
    "sourceIds": ["SRC-000"],
    "status": "supported|partial|unverified|refuted|monitoring",
    "notes": { "review": "по замечанию №… рецензии <раздел>" }
  }
]
```
