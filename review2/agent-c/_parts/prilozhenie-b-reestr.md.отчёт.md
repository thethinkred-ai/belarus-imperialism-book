**Вердикт рецензии:** требует переработки — приложение отстаёт от реестра (жёсткие счётчики, устаревший словарь
статусов, статический перечень источников, незавершённый пример CLM-033).

## Замечания и решения

**№1 / устаревшие счётчики 34 SRC и 53 CLM в §Б.1–Б.2 и ручной перечень §Б.6 → [ПРИНЯТО] →** числа удалены,
источники и утверждения не перечисляются: отсылка к `sources/registry.json` и кнопке экспорта (§Б.1, шапка
приложения: «число источников и утверждений не фиксируется»). Полный список заменён тематической картой §Б.3.

**№2 / словарь статусов приложения не совпадает со стандартом → [ПРИНЯТО] →** §Б.5 разделён на «Уровень 1 — статус
карточки» (`supported` / `partial` / `unverified` / `refuted` / `monitoring`, служебные метки) и «Уровень 2 — итоговый
статус вывода» (ДОКАЗАНО / НЕ ДОКАЗАНО (ОТКРЫТО) / ОПРОВЕРГНУТО / НЕПРИМЕНИМО). Добавлено «Правило перехода между
уровнями»: статус карточки не переносится в текст автоматически.

**№3 / пример CLM-033 без текущего статуса и без границ вывода → [ПРИНЯТО] →** §Б.4 переписан в пять шагов:
v0.5 (unverified) → v0.6.1 (прокси GNI − GDP) → v0.6.2 (прямые строки) → текущее состояние карточки (`supported`,
сверка 2026-10-10) → пределы вывода. Формулировка рецензии взята дословно по смыслу: подтверждение агрегата не
устанавливает получателей потоков и механизмы присвоения.

**№4 / §Б.5 не описывает схему реестра (колонки ID / Главы / Статус / Текст / Источники) → [ПРИНЯТО] →** §Б.1
описывает карточку CLM с колонкой «Главы» и её роль в сквозной трассировке; §Б.5 поясняет, что отсутствие привязки к
источнику — незавершённая трассировка, а не доказательство отсутствия данных.

**№5 / политика ссылок «по запросу» → [ПРИНЯТО] →** §Б.3, блок «Правовая дисциплина ссылок»: только формула
«источник доступен по запросу», без активных ссылок и доменных имён; перечень и основания — прил. Г (§Г.3).

**№6 / проверить, как описаны CLM-067–082 → [ПРИНЯТО] →** §Б.6: тематическая карта новых групп (7 строк) с
ориентирами по карточкам. Каждая строка сверена с текстом карточки в снимке реестра (см. «Сверка» ниже).

**№7 / диапазон CLM-067–082 устарел, есть CLM-083 → [ПРИНЯТО] →** диапазон в приложении не фиксируется:
«карта начиная с CLM-067», в таблице CLM-079 и CLM-083 стоят рядом (Периодизация и классификация).

**№8 / жёсткие счётчики реестра («62 SRC / 83 CLM») → [ОТКЛОНЕНО] →** основание: стандарт. Приложение отображает
реестр, а не фиксирует его слепок; жёсткие числа снова устареют. Сверка фактического состава (62 SRC / 83 CLM на
2026-10-10) вынесена в отчёт, не в текст приложения.

**№9 / пример, показывающий подтверждённый показатель при открытом механизме присвоения → [ПРИНЯТО] →** §Б.5,
абзац «Разрезы»: CLM-033 (агрегат подтверждён) против CLM-060 (внешний рычаг) и CLM-062 / CLM-078 (НЕ ДОКАЗАНО
(ОТКРЫТО) при подтверждённой концентрации).

**№10 / правило надёжности источника относительно типа утверждения → [ПРИНЯТО] →** §Б.5, правило 3 формулировки.

**№11 / инструкция чтения связанных CLM из разных глав → [ПРИНЯТО] →** §Б.6: порядок из четырёх шагов (колонка
«Главы» → статус вывода в самой поздней главе с пояснением усиления → различение доли, доступа и влияния →
открытое звено остаётся открытым) + опорные связки по четырём сквозным явлениям.

**№12 / миграция и ИИ: как читать и как вводить новые темы → [ПРИНЯТО] →** §Б.6, абзац «Как новая тема попадает в
реестр»: тезис, тип, источники и ограничения определяются до присвоения номера CLM; до этого — `[задание]`.

**№13 / убрать дублирование §Б.1, §Б.2, §Б.3 и §Б.6 → [ПРИНЯТО] →** перечень источников удалён, §Б.3 сведён к
тематическим группам без повторов, §Б.2 больше не пересказывает статусы.

**№14 / перенести историю версий в компактную схему → [ЧАСТИЧНО] →** §Б.4 сохранён нумерованным списком из пяти
шагов (история изменения статуса — содержательный элемент примера); сжат по формулировкам, не сведён в схему.

**№15 / правило «не установлено» ≠ «отсутствует» → [ПРИНЯТО] →** §Б.5, правило 1; здесь же различение
эпистемического и онтологического статуса.

## Сверка с реестром и с главами (правило 13)

Снимок `книга/registry.json` на 2026-10-10: 62 источника SRC, 83 утверждения CLM. Приложение не содержит
собственных чисел; расхождений по формулировкам не выявлено, кроме отмеченных ниже.

Статусы CLM, упоминаемых в приложении, сверены с переработанными главами в `agent-c\`:

- CLM-033 — приложение: карточка `supported`, итоговый статус вывода **НЕ ДОКАЗАНО (ОТКРЫТО)**, агрегат доказан.
  Гл. 9 §9.5: «Пока механизм не установлен, статус [Л-3] — НЕ ДОКАЗАНО (ОТКРЫТО)». Совпадает; статус не усилен.
- CLM-060 — приложение: «внешний рычаг, а не установленное присвоение». Гл. 12 §12.5 и §12.4: то же
  («логистика ≠ контроль сбыта», В — НЕ ДОКАЗАНО (ОТКРЫТО)). Совпадает.
- CLM-062, CLM-078 — приложение: способность навязывать условия рынка — **НЕ ДОКАЗАНО (ОТКРЫТО)**.
  Гл. 12 §12.5: В — НЕ ДОКАЗАНО (ОТКРЫТО), К и Р — ДОКАЗАНО по данным концентрации. Совпадает.
- CLM-067…CLM-083 — в приложении приведены как навигационные ориентиры тематических групп, без утверждения
  статусов; расхождений с карточками нет.

Итог: статусы, заявленные приложением, не сильнее статусов глав. Корректировок по правилу 13 не потребовалось;
расхождений, требующих правки приложения, не выявлено. Приложение Г не редактировалось — правовой статус
источников остаётся его предметом.

## Спорные места и конфликты со стандартом

1. Жёсткие счётчики реестра. Рецензия предлагает «62 SRC / 83 CLM»; стандарт требует, чтобы приложение отображало
   реестр, а не дублировало его слепок. Решение в пользу стандарта (отклонение №8), компромисс — сверка в отчёте.
2. «Подтверждено с ограничением данных» в §Б.5 — это словарь реестра (`partial`), а не статус знания; в тексте
   приложения оно явно помечено как не равное «не доказано», поэтому подмены статусов нет.
3. Расхождение чисел CLM-033 между снимком реестра (2024: −1,8 млрд $) и гл. 9 (−2,6 млрд $) — приложение следует
   карточке CLM-033; гл. 9 вне зоны ответственности прил. Б, вопрос вынесен на сверку с владельцем главы.
4. Статус «не установлено» (CLM-081, гл. 13) в приложении не цитируется, чтобы не смешивать словари.
